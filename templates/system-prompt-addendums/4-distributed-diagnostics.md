## Copy the block below as the System Prompt Addendum or Agent Instructions:

```markdown
# Multi-Service Log Correlation & Diagnostics Protocol

When tasked with debugging complex integrations, multi-process loops, frontend-backend mismatches, or distributed server crashes, you must avoid dumping raw, unparsed logs directly into the main thread. Follow this systematic debugging protocol:

1. **Systematic Log Ingestion:**
   - Instead of asking the user to paste log dumps or piping massive terminal dumps into your chat window, collect isolated log blocks from each individual system (e.g., Docker, Nginx, PostgreSQL, Browser Console).
   - Use the `correlate_errors` tool, mapping each log block to its corresponding system name (e.g., `[ { "system_name": "db", "content": "..." }, { "system_name": "backend", "content": "..." } ]`).

2. **Root Cause Analysis Synthesis:**
   - Review the synthesized JSON output generated by `correlate_errors` (processed under the hood by a specialized Reliability Engineer persona).
   - Base your final bug-fix or remediation code directly on the correlated timeline and root-cause analysis provided by the tool, highlighting system-level intersections.
```

---

## How It Is Used & Why It Is Useful

### How It Is Used:
* **Ingestion:** Place this block in the system prompt of DevOps bots, terminal coding assistants, or site reliability engineering agents.
* **Execution:** When the agent executes integration tests that fail, it will systematically harvest logs from the running database container and the backend application service. It then sends them to `correlate_errors` to parse timing mismatches or transaction rollbacks, outputting a neat structural diagnosis.

### Why It Is Useful:
* **Prevents Context Swamping:** Pasting raw, unstructured 500-line server logs into an agent's main chat window pollutes the conversational context, causing the agent to lose track of earlier files or guidelines. This segregates raw log analysis into a clean external tool.
* **Identifies Quiet Mismatches:** Sometimes a database query fails quietly and the backend reports a generic `500 Internal Server Error`. Correlating both logs side-by-side allows the agent to spot the exact database constraint violation that triggered the backend crash.
